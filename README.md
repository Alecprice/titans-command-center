# Titans Command Center

A mobile-first, installable Tennessee Titans fan HQ and data PWA. It combines current team information, game-day context, roster and transaction snapshots, free market-data adapters, player intelligence, franchise history, optional fan personalization, and a Neon Postgres warehouse behind a custom Titans-focused UI.

## Current platform — app v1.0.0 / 2026 fan PWA

The project follows a **content-integrity first** model. Current facts are checked against TennesseeTitans.com first, then NFL.com where appropriate. The Pro Football Hall of Fame, Pro Football Reference, nflverse, SportsLogos.net and Wikipedia are secondary/cross-check sources by domain rather than interchangeable authorities.

### Production architecture

- GitHub `main` is the production source branch.
- Production deploys to a **Cloudflare Worker** with bundled static assets; `/api/*` is handled by the Worker before static fallback.
- `wrangler.jsonc` is the authoritative runtime configuration and requires `DATABASE_URL` as a Worker secret.
- Neon Postgres is the production data store; clearly labeled local/cached data remains the offline or database-failure fallback where supported.
- Cloudflare deployment runs the repository quality gate before deploy, then production API and browser regressions across navigation, Listen / Watch, Command Intelligence, Player Intelligence / Game Day, Ask Titans, Change Intelligence, Runtime / 365 Mode, Account / Guest, analytics, and headshots.
- `docs/CLOUDFLARE_STATUS.md` is generated by the deployment workflow and is the repository record for the last production deployment pass.
- Any remaining Vercel GitHub check is **legacy and non-authoritative** for production. The active app is Cloudflare-hosted.

### Fan experience working now

- Installable PWA with phone, tablet/small-laptop, desktop, and wide-desktop layouts.
- Five-action mobile dock: Home, Roster, Game, Search, and More.
- 365 Mode changes home priorities based on the football calendar without pretending unofficial dates are league-defined windows.
- Smart search for players, jersey numbers, positions, weeks, roster moves, next home games, injuries, history, stats, and app sections.
- Customizable home command deck with reorderable/hideable game, favorite-player, roster-move, intel, market, and freshness cards.
- Player intelligence, favorites, position-aware comparison, schedule detail expansion, Game Day, analytics, market context, Listen / Watch, legacy navigation, and change intelligence.
- Optional accounts with guest-first access. Signing in is never required to browse the app.
- Selected signed-in preferences can sync across devices through the account preference API; guest settings remain browser-local.
- Browser/PWA reliability includes saved data fallback, offline messaging, pull-to-refresh, route recovery, scroll restoration, service-worker update handling, and production browser smoke coverage.
- API/auth responses are never PWA-cached.

### Audited football-data baseline

The repository keeps dated source assertions rather than silently presenting old snapshots as live facts.

- Current official roster snapshot recorded in the Aug. 19 audit: **91 Active + 4 Reserve/Injured = 95 players**.
- Aug. 19 roster move recorded: **RB D'Ernest Johnson signed; RB Dominic Richardson waived**.
- Week 9 is the 2026 bye; Week 18 at Houston remains **TBD** in the audited schedule baseline and the official venue name used by the project is **Reliant Stadium**.
- Official transaction chronology is stored through Aug. 19 in the current audited dataset.
- Team Room includes a dated official **UNOFFICIAL** depth-chart snapshot with ties preserved, plus current leadership and the audited coaching staff snapshot.
- Stats Lab separates verified prior-season baselines from not-yet-complete 2026 regular-season totals and exposes known source conflicts instead of filling gaps with guesses.
- The current visual treatment uses Titans Blue-led branding and verified current marks; historical/reference imagery remains separately labeled.

### Source checks vs. persistence

A reachable provider is **not** the same thing as an active warehouse importer.

- The protected scheduled endpoint runs a `daily-source-check`, not a fake “deep refresh.”
- Official Titans roster/transactions/schedule/depth-chart pages receive reachability/marker checks without unverified HTML parsing into production data.
- Every source-check outcome is logged to Neon `sync_runs` as `success`, `skipped`, or `failed`, with records seen/written kept separate.
- Skipped nflverse/NWS persistence jobs do not count as successful refreshes.
- ESPN and Bluesky can be reachable while writing zero rows; their source status says so.
- Market persistence remains disabled until live provider payloads are fully verified.

## Source hierarchy

1. **Roster / schedule / transactions / staff:** TennesseeTitans.com, with NFL.com as official cross-check where applicable.
2. **Statistics:** structured Tennessee Titans team-stat tables first; NFL.com, Pro Football Reference and nflverse as cross-checks. Editorial recap copy does not override the structured table.
3. **Injuries:** official Titans injury report. Reserve/Injured roster status is separate, and “no report yet” never means zero injuries.
4. **History:** Titans official history plus the Pro Football Hall of Fame; PFR/Wikipedia are secondary.
5. **Visual identity:** Titans brand/history pages first, SportsLogos.net second. User-supplied art is reference material unless an exact mark/year is verified.

Known discrepancies are surfaced in the Sources page rather than hidden. One recorded example: the official Aug. 1 transaction table says “Mario Goodson III,” while the current official roster and dedicated Titans signing story identify **Mario Goodrich III**; the app keeps the roster/news identity and records the transaction-table typo.

## Local development

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open `http://localhost:4173`.

## Quality checks

```bash
npm run check
```

This runs Node regression tests, factual-content assertions, credential/secret scanning, recursive JavaScript syntax checks, the Cloudflare build, and Cloudflare build verification.

## Cloudflare deployment

```bash
npm run deploy:cloudflare
```

Production deployment is normally handled by `.github/workflows/cloudflare-deploy.yml` after changes reach `main`. The workflow requires GitHub secrets for Cloudflare credentials and `DATABASE_URL`.

## Core API surface

Public and protected API routes are dispatched by `cloudflare/worker.mjs`. Core routes include:

- `GET /api/health`
- `GET /api/provider-health` — protected diagnostics
- `GET /api/data`
- `GET /api/fan-intel`
- `GET /api/espn-scoreboard`
- `GET /api/bluesky-search?q=...`
- `GET /api/odds`
- `GET /api/player?id=...`
- `GET /api/analytics?...`
- `GET /api/preseason-stats`
- `POST /api/sync?job=...` — protected
- `GET /api/cron-refresh` — protected scheduled source check
- `/api/account/auth/*` — narrow same-origin managed-auth proxy
- `GET|PUT /api/account/preferences` — authenticated optional preference sync

## Free/no-card policy

Core dependencies should remain usable at $0 without entering a payment card where practical. Server credentials belong only in environment configuration and must never be committed or shipped to browser JavaScript.

## Database

Neon is the production Postgres service. Seed data is intentionally conservative and never pretends to be a live roster.

Notable migrations include:

- `008_content_integrity_20260819.sql` — initial schedule/roster/transaction integrity corrections.
- `009_current_audit_20260819.sql` — Aug. 19 roster move, Reliant Stadium correction, and honest integration-status metadata.
- `20260822_fan_user_preferences.sql` — optional account-synced fan preferences. It is intentionally **manual**; Cloudflare deployment does not apply database migrations automatically.
