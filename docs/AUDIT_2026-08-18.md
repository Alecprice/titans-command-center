# Titans Command Center Audit — 2026-08-18

## Primary 403 finding

The Vercel 403 observed while creating deployments is outside the application runtime. The connected Vercel session exposed only the `Tower Defense2` team and `eifs-quotes` project, and both preview/production creation were rejected before a Titans build existed. The ChatGPT-side Vercel integration permission was already set to allow all actions.

The application itself now has explicit route behavior:

- `GET /api/sync` → 405
- unauthorized `POST /api/sync` → 401
- authorized ingestion without `DATABASE_URL` → 503
- unauthorized `/api/provider-health` → 401 when admin auth is configured
- public `/api/odds` with arbitrary query parameters → 400

There is no Vercel-runtime application route that returns 403.

## Fixes applied in v0.5.2

1. Service worker no longer intercepts or caches `/api/*`; stale auth/errors cannot persist in PWA cache.
2. State-changing ingestion is POST-only.
3. Provider-health probing is protected by server-side admin auth so public traffic cannot burn free API quota.
4. Public odds refresh has one canonical URL, rejects cache-busting query parameters, adds CDN + warm-instance coalescing, and leaves deep two-provider cross-checks to protected ingestion.
5. Local development now invokes the exact same API handler modules used by Vercel instead of duplicated route implementations.
6. Added CSP, frame denial, permissions policy, and safer outbound URL handling.
7. Escaped additional provider/database-derived UI values.
8. Public endpoints no longer return raw internal database/provider exception strings.
9. Cron jobs run independent refreshes concurrently and report partial success/failure counts.
10. Manual sync requires an explicit job selection to avoid accidental all-provider heavy runs.
11. Added `.env.example` and aligned the in-app copied template with actual free-only variables.
12. Secret scanner now scans `.env.example` and recognizes additional Neon/API-key credential shapes.
13. Full recursive JavaScript syntax checking replaces the old hand-maintained subset.
14. Neon driver is pinned to an exact version for reproducible deployments.
15. Repository schema metadata aligned with live Neon schema v0.6.0; app metadata is v0.5.2.
